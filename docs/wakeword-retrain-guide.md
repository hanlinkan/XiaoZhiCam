# 唤醒词：怎么保证重训是有效的

> 本文只讨论「先建立什么，才有资格重训」，不包含训练步骤。
> 训练脚本与数据在 `src/kws/test/`、开发机训练目录，不随本仓库分发。

## 结论先行

**先别重训。** 目前不具备判断「新模型比旧模型好」的条件。

历史上已经重训过 v4→v16 共十余版，每一版都能在离线指标上进步，但真机仍出现
「没说唤醒词就进对话」。问题不在训练代码，而在**验证闭环**：没有固定的效果回归集、
没有证据证明负样本真的进了训练、真机误报留不下音频、离线指标和设备真值口径不一致。

一句话：**先造尺子，再练模型。**

---

## 一、现在为什么不能保证效果

| 缺口 | 具体表现 | 后果 |
|---|---|---|
| 负样本是否进训练没有断言 | 内部记录 07 补记明说「没有任何一处日志能证明负样本真的进入训练」，验证集 `faph=nan` | 调参可能是盲调；v7 出现过「负样本越多、误报越多」 |
| 离线评测口径与设备不一致 | `eval_engine` 用窗口概率（乐观）；设备真值必须走 `kws_host`（含门控/冷却）。内部记录 09：v9 的 94% 召回在设备语义下约 48% | 离线好看，上机翻车 |
| 评估集缺前置静音会差三倍 | 同一模型同一参数，不补 1 s 底噪召回 29%，补了 85% | 评测方法本身能决定结论 |
| 负样本量与覆盖不足 | 可用底噪只有 14 分钟、一个房间一个时段；旧负样本电平比现网低 16~24 dB | 按三倍法则，321 s 无 FP 只能宣称 95% 上界 ≈34 次/小时 |
| 真机误报无法复现 | 现在只留 `[kws] HIT ... prob/rel/floor` 文本日志，没有当时音频 | 每次误报都靠猜，无法转成训练样本 |
| CI 只验「没算错」，不验「效果没退化」 | 现有 workflow 只跑 mel / 网络逐位金标 | 模型换了、效果退了，CI 照样全绿 |

**特别提醒**：「现在几点了」这类指令问句**已经在 v16 的训练负样本里**——
合成指令 498 条、真机指令实录 600 s、定向挖掘 41.7 s 误报点（`sampling_weight: 30`），
真机仍给 255 分。所以「再补一批同类样本」不等于能修好：要么这些样本没真正进训练，
要么真机的说话人、距离、混响、电平与它们不在同一个域。

**近音负样本同理，但结论更明确**：162 条「你好小志 / 小智小智」这类 TTS 合成近音词，
历史上没有证明能压误报——v6 / v8 加了之后误报反而到 56 / 179 次每小时，
v15 真正生效靠的是把负样本换成**真机单声道指令实拍**。当前误报是「不相干的中文句子」，
不是「相似词混淆」，两者不是一回事。建议把这批从训练集里降权或移除，
只留几十条放进**固定评测集**当防回归护栏（确认新模型没顺手把近音词也放行）。

## 二、四把尺子（按建立顺序）

### 尺子 1：训练前的数据断言

在训练数据加载处打印并在 CI 里断言：

- 正 / 负样本的条数与总时长、每个 batch 的负样本占比
- 每类负样本（底噪 / 指令问句 / 近音词 / TTS 回放 / 定向挖掘）的实际条数
- 验证集必须包含各类负样本，`ambient_false_positives_per_hour` 不能是 `nan`

没有这些数字，训练结果不可解释——这是内部记录 07 留下的明确结论。

### 尺子 2：同分布的特征与评测

- 训练特征必须由**固件同一份 C 链路**生成（v16 已做到，与连续流逐位一致，不要退回 pymicro）
- 每个片段前置 ≥1 s 真机底噪预热，模拟「设备空闲 → 用户开口」
- 离线评估统一走 `kws_host` 连续流模式，报告设备语义命中数，不用窗口概率
- 录音口径固定为 8 kHz 单声道原始流（历史上「取左声道」曾把流抽稀一半，影响数日评测）

### 尺子 3：固定回归集 + 量化门槛

建一个**版本化、训练过程中不许改动**的测试集：

- 正样本：≥3 个说话人 × 3 种距离 × 正常/偏快/偏慢语速，每条前置底噪
- 负样本：跨时段、跨房间底噪 ≥6 h；日常指令问句；近音词；TTS 回放；家电噪声
- 划分按「说话人 + 录制会话」分组，防止同一段录音同时进训练和测试

建议门槛（写进选模条件）：

| 指标 | 门槛 |
|---|---|
| 真词召回（设备语义） | ≥ 90% |
| 环境误报 | ≤ 0.5 次/小时 |
| 回归 | 旧版能过的正样本，新版一条都不许丢 |
| 资源 | 单核开销 ≤ 15%、模型体积不增 |

**置信度**：观测到 0 次误报时，95% 置信上界约 `3 / T`（T = 负样本小时数）。
要宣称 <0.5 次/小时，需要约 **6 小时**无 FP 的负样本；跑 5 分钟「0 误报」没有统计意义。

### 尺子 4：真机留证与误报回流

- 在 `p8_client.c` 命中分支加一个默认关闭的录音开关：把 HIT 前后各 2~3 s 的
  8 kHz 原始抽头写到 SD 卡（只写内存盘/标记触发，避免长期磨损）
- 每次误唤醒自动留一段音频 + 当时的 `prob / rel / floor / state`
- 定期把误报片段回流成定向负样本（v16 的定向挖掘就是手工版）
- 上机走 A/B：新旧模型各跑一段，比较真实误报数与真词召回，保留可回滚的模型 hash

---

## 三、重训前的落地清单

- [ ] 训练脚本加数据断言，跑一次确认负样本确实进 batch
- [ ] 把 `kws_host` 设备语义评测固化成一条命令 + 固定回归集（版本化）
- [ ] 把效果回归接进 CI（现有 CI 只有逐位金标）
- [ ] 相机端加「误报留证」开关，先采 1~2 周真实误报
- [ ] 补录跨时段 / 多房间底噪 ≥6 h + 真人指令问句（多说话人、多距离）
- [ ] 定下量化门槛与回滚方案，**然后**再开始训练

---

## 四、最容易复发的三个坑

1. **评测口径**：不补前置静音，召回从 85% 掉到 29%，会把调参带向错误方向
2. **特征链路**：训练用 pymicro、部署用固件 C，同一个「你好小智」255 分 vs 105 分
3. **指标乐观**：窗口概率 ≠ 设备语义，`eval_engine` 的召回不能当验收依据

这三件事都不是「模型不够大」，加数据之前先把它们钉死，否则重训多少版都会重演。
