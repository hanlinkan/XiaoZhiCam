# 唤醒词：怎么保证重训是有效的

> 本文只讨论「先建立什么，才有资格重训」，不包含训练步骤。
> 训练脚本与数据在 `src/kws/test/`、开发机训练目录，不随本仓库分发。

## 结论先行

**先别重训。** 目前不具备判断「新模型比旧模型好」的条件。

历史上已经重训过 v4→v16 共十余版，每一版都能在离线指标上进步，但真机仍出现
「没说唤醒词就进对话」。问题不在训练代码，而在**验证闭环**：没有固定的效果回归集、
没有证据证明负样本真的进了训练、真机误报留不下音频、离线指标和设备真值口径不一致。

一句话：**先造尺子，再练模型。**

---

## 一、现在为什么不能保证效果

| 缺口 | 具体表现 | 后果 |
|---|---|---|
| 负样本是否进训练没有断言 | 内部记录 07 补记明说「没有任何一处日志能证明负样本真的进入训练」，验证集 `faph=nan` | 调参可能是盲调；v7 出现过「负样本越多、误报越多」 |
| 离线评测口径与设备不一致 | `eval_engine` 用窗口概率（乐观）；设备真值必须走 `kws_host`（含门控/冷却）。内部记录 09：v9 的 94% 召回在设备语义下约 48% | 离线好看，上机翻车 |
| 评估集缺前置静音会差三倍 | 同一模型同一参数，不补 1 s 底噪召回 29%，补了 85% | 评测方法本身能决定结论 |
| 负样本量与覆盖不足 | 可用底噪只有 14 分钟、一个房间一个时段；旧负样本电平比现网低 16~24 dB | 按三倍法则，321 s 无 FP 只能宣称 95% 上界 ≈34 次/小时 |
| 真机误报无法复现 | 现在只留 `[kws] HIT ... prob/rel/floor` 文本日志，没有当时音频 | 每次误报都靠猜，无法转成训练样本 |
| CI 只验「没算错」，不验「效果没退化」 | 现有 workflow 只跑 mel / 网络逐位金标 | 模型换了、效果退了，CI 照样全绿 |

**特别提醒**：「现在几点了」这类指令问句**已经在 v16 的训练负样本里**——
合成指令 498 条、真机指令实录 600 s、定向挖掘 41.7 s 误报点（`sampling_weight: 30`），
真机仍给 255 分。所以「再补一批同类样本」不等于能修好：要么这些样本没真正进训练，
要么真机的说话人、距离、混响、电平与它们不在同一个域。

**近音负样本同理，但结论更明确**：162 条「你好小志 / 小智小智」这类 TTS 合成近音词，
历史上没有证明能压误报——v6 / v8 加了之后误报反而到 56 / 179 次每小时，
v15 真正生效靠的是把负样本换成**真机单声道指令实拍**。当前误报是「不相干的中文句子」，
不是「相似词混淆」，两者不是一回事。建议把这批从训练集里降权或移除，
只留几十条放进**固定评测集**当防回归护栏（确认新模型没顺手把近音词也放行）。

## 二、四把尺子（按建立顺序）

### 尺子 1：训练前的数据断言

在训练数据加载处打印并在 CI 里断言：

- 正 / 负样本的条数与总时长、每个 batch 的负样本占比
- 每类负样本（底噪 / 指令问句 / 近音词 / TTS 回放 / 定向挖掘）的实际条数
- 验证集必须包含各类负样本，`ambient_false_positives_per_hour` 不能是 `nan`

没有这些数字，训练结果不可解释——这是内部记录 07 留下的明确结论。

### 尺子 2：同分布的特征与评测

- 训练特征必须由**固件同一份 C 链路**生成（v16 已做到，与连续流逐位一致，不要退回 pymicro）
- 每个片段前置 ≥1 s 真机底噪预热，模拟「设备空闲 → 用户开口」
- 离线评估统一走 `kws_host` 连续流模式，报告设备语义命中数，不用窗口概率
- 录音口径固定为 8 kHz 单声道原始流（历史上「取左声道」曾把流抽稀一半，影响数日评测）

### 尺子 3：固定回归集 + 量化门槛

建一个**版本化、训练过程中不许改动**的测试集：

- **零真人录制**：素材全部来自公开语料与 AI 合成，不组织任何真人录音。
- **说话人 / 音色无关是硬要求**。负样本若只来自一个音色，模型会走捷径学
  「这个音色 = 不该醒」而不是学「词是什么」；正样本又是以单一 TTS 音色为主，
  最省力的解法学成「听见真人说话就醒」——正是当前误报的形态。
- 正样本：AI 多音色 TTS 生成「你好小智」，用不同音色 / 语速 / RIR 房间卷积 /
  增益变化模拟距离；每条前置底噪
- 负样本：**同一批 AI 音色**说不相干句子 + AISHELL-1 公开多说话人语料
  + 跨时段 / 跨房间环境音 ≥6 h + TTS 回放 + 家电噪声
- 划分按「AI 音色 ID + 语料说话人 ID」分组，测试集里的音色和说话人与训练
  **零交集**：edge-tts 留 2 个音色只用于测试，AISHELL 留出 15% 说话人；
  按组报告召回，别只看平均值（否则某个群体特别差会被平均掩盖）

**如实标注的能力边界**：正样本全是合成语音，「真实人声说唤醒词」的召回无法在
离线考卷里直接验证。负样本侧的公开真人语料（AISHELL）提供声学覆盖，上线前再用
真机 A/B 验收。这是可接受的取舍，不靠组织真人录音来补。

建议门槛（写进选模条件）：

| 指标 | 门槛 |
|---|---|
| 真词召回（设备语义） | ≥ 90% |
| 环境误报 | ≤ 0.5 次/小时 |
| 回归 | 旧版能过的正样本，新版一条都不许丢 |
| 资源 | 单核开销 ≤ 15%、模型体积不增 |

**置信度**：观测到 0 次误报时，95% 置信上界约 `3 / T`（T = 负样本小时数）。
要宣称 <0.5 次/小时，需要约 **6 小时**无 FP 的负样本；跑 5 分钟「0 误报」没有统计意义。

### 尺子 4：真机留证与误报回流

- 在 `p8_client.c` 命中分支加一个默认关闭的录音开关：把 HIT 前后各 2~3 s 的
  8 kHz 原始抽头写到 SD 卡（只写内存盘/标记触发，避免长期磨损）
- ⚠️ **这些留证只用于复现与定位**（回答「刚才那句为什么被当成唤醒」）。
  它数量少、只有一个说话人，**不能直接当训练主料**，否则会把模型带向说话人过拟合。
  要进训练集，必须按尺子 3 补齐多说话人并做分组划分
- 每次误唤醒自动留一段音频 + 当时的 `prob / rel / floor / state`
- 定期把误报片段回流成定向负样本（v16 的定向挖掘就是手工版）
- 上机走 A/B：新旧模型各跑一段，比较真实误报数与真词召回，保留可回滚的模型 hash

## 四、最容易复发的三个坑

1. **评测口径**：不补前置静音，召回从 85% 掉到 29%，会把调参带向错误方向
2. **特征链路**：训练用 pymicro、部署用固件 C，同一个「你好小智」255 分 vs 105 分
3. **指标乐观**：窗口概率 ≠ 设备语义，`eval_engine` 的召回不能当验收依据

这三件事都不是「模型不够大」，加数据之前先把它们钉死，否则重训多少版都会重演。

## 五、现有数据资产盘点（开发机，2026-11-07）

| 资产 | 现状 | 能否用于重训 |
|---|---|---|
| AISHELL-1（6.0 GB，约 165 h / 400 说话人，16 kHz） | 压缩包未解压，按说话人分卷 | ✅ 多说话人负样本主料 |
| Common Voice 中文 | 目录为空，下载未完成 | ❌ 暂不可用 |
| 真机底噪（30 分钟 + 长时录音） | 已有 | ✅ 预热与叠加 |
| MIT RIRS 房间冲激响应（270 个房间） | 已有 | ✅ 给合成语音加真实混响 |
| 真人真词 | 48 条历史素材，主要来自单一说话人 | ⚠️ 仅供参考，不依赖、不再补录 |
| TTS 音色 | piper 1 个；训练环境另有 edge-tts（多音色）、torch | ✅ 可扩充正样本音色 |
| `libkwsfeat.so` + `mww_deploy_features.py` | 已有：吃 8 kHz int16、320 点连续流、前置 2 s 底噪 | ✅ 链路现成 |
| `gen_noise_features.py` / `eval_engine.to8k` | 已有连续流特征 / 16k→8k 降采样 | ✅ 适配器可直接复用 |

**结论：公开语料不能「直接」过链路（格式是 16 kHz，链路吃 8 kHz），但改造很小，
且不用动固件**：解压 → 16k→8k 抗混叠降采样 → 叠真机底噪 + RIR 卷积 + 电平对齐
→ 前置 2 s 底噪预热 → `libkwsfeat.so` 连续提特征 → 按说话人分组切窗口与
train / val / test。只缺一个批量适配器脚本。

**正样本用 AI 生成多音色是可行的**，但有个前提：让**同一批音色既说「你好小智」
也说一堆不相干句子**。否则正负样本的音色分布不一致，模型仍会学音色捷径。
测试集要留出训练里完全没见过的**音色和语料说话人**（AI 音色留 2 个、
AISHELL 留 15% 说话人），不能全是训练见过的声音自己考自己。

## 六、已落地的工具（2026-11-07）

`src/kws/test/` 下三个脚本，负责把第五章的资产变成可训练素材，**不动固件**：

| 脚本 | 作用 |
|---|---|
| `corpus_common.py` | 公共模块：16k WAV 读写、RIR 卷积、真机底噪叠加、固件 C 链路特征、变长窗口、按说话人分组、RaggedMmap 输出、MP3 解码 |
| `prepare_public_corpus.py` | 流式读 AISHELL-1 外层 tgz → 多说话人**负样本特征**，按说话人切 train/val/test |
| `gen_multivoice.py` | edge-tts 多个 zh-CN 音色，**同一批音色**既生成「你好小智」也生成不相干句子；`--holdout-voices N` 把末尾 N 个音色留作考卷（只进 testing，默认 2），`--negative-features` 直接产负句特征 |

设计约束：

- 特征一律走 `libkwsfeat.so`（`make libkwsfeat.so` 本地构建，`.gitignore` 忽略、不入库）；
  可用 `KWSFEAT_LIB` 指向别处已编好的那份
- 真机底噪显式传 `--noise`，不依赖历史 `~/mww_data` 软链
- MP3 解码用开发机资产清单 §5 登记的 `~/bin/ffmpeg`；它不在非交互 ssh 的 PATH 里，
  按清单 §2 用 `bash -lc` 探测，**不能用 `which` 单点判断**
- RIR / 背景噪声增强默认关闭：`gen_features_deploy.py` 的 Augmentation 自带
  RIR(0.5) 与背景噪声(0.75)，避免双重增强
- 窗口变长（≥150 帧），用 pickle 缓存 + RaggedMmap 输出，支持 `--resume`；
  所有随机性来自 `--seed`，`manifest.json` 记录参数、说话人分组与文件清单

```bash
# 本机先构建特征库（不入库）
make -C src/kws/test libkwsfeat.so

# 多说话人负样本（冒烟用 3 人 × 5 条）
python prepare_public_corpus.py \
  --aishell <AISHELL-1 tgz> --out <features_public_v1> \
  --speakers 20 --per-speaker 40 --seed 1234 --resume

# 多音色正负句（冒烟用 --voice-count 3 --pos-per-voice 1 --neg-per-voice 2）
python gen_multivoice.py --out <multivoice_v1> \
  --pos-per-voice 6 --neg-per-voice 24 --holdout-voices 2 --negative-features
```

**正样本 WAV 交给 `gen_features_deploy.py`**（它负责标签对齐与增强）；
负样本特征可直接作为训练配置里的 `features_dir`。
测试集由「留出未参与训练的 AI 音色 + 留出的 AISHELL 说话人」组成，与训练零交集；
**全程不需要任何真人录音**。

冒烟验证（开发机实测）：AISHELL 3 人 × 5 条 → 28 个窗口、按人分到 3 个 split，
特征 `(309, 40)` float32、值域 0~23.5；3 音色 × 1 正 2 负 → 9 个 WAV +
3 个 split 的负句特征（变长 168~196 帧），均可被 `RaggedMmap` 正常读出。

## 七、评测闭环工具与真实配置体检（2026-11-07）

| 工具 | 作用 |
|---|---|
| `verify_training_data.py` | 训练前独立断言：目录存在性、各 split 条数、正负样本比例、按 `sampling_weight` 模拟 batch 负样本占比、validation/testing 必须有负样本、留出音色与训练零交集。失败 exit 1 |
| `eval_retrain.py` + `eval_thresholds.json` | 固定考卷判卷：总召回 / 按组召回、误报率（次/小时）、负样本时长、回归检查、CPU。达标 exit 0 |
| `.github/workflows/build.yml` 的 `data-gates` job | 跑上面两个脚本的 `--self-test`（公开仓库不含数据与模型） |

门槛：召回 ≥90%、误报 ≤0.5 次/小时、负样本 ≥6 小时、单核 ≤15%、
旧版能过的正样本一条都不许丢。误报为 0 时按三倍法则报告 95% 置信上界 `3/T`。

**真实配置体检（重要发现）**：拿 `training_parameters_v16.yaml` 跑
`verify_training_data.py`，结果是 **6 个 `./data/features_v9_* / v12_* / v13_*`
目录在开发机上已不存在**，只剩 3 个 v15/v16 目录有数据
（负样本 training 1501 / validation 53 / testing 44），而**正样本 training = 0**，
模拟 batch 负样本占比 0.944。也就是说 v16 训练时用的 `./data/` 已被清理，
**直接拿这份配置重训会静默跳过大部分素材**。重训前必须用第六章脚本重新生成
全套特征并复检通过——这正印证了「没有任何日志能证明负样本进了训练」那条历史教训。

第一批全量数据（开发机实测，27 s）：AISHELL 50 说话人 × 60 条 → 4688 个窗口，
按人分为 training 34 人 / 3243、validation 8 人 / 714、testing 8 人 / 731。
多音色第一批（302 s）：8 音色 × 4 正 + 12 负 = 128 个 WAV，
负句特征 training 51 / validation 10 / testing 23（留出音色，与训练零交集）。

**重训前仍缺**：正样本 WAV 散落在 `positive/<voice>/` 子目录，需摊平后经
`gen_features_deploy.py` 生成特征；旧 v9/v12/v13 特征目录需按新链路重建；
`training_parameters_v17.yaml` 尚未建立。这三件做完并让 `verify_training_data.py`
全绿，才具备重训条件。
